# הכתוביות

## טיפוגרפיה

**Heebo 900** דרך `@remotion/google-fonts/Heebo`.

```ts
import {loadFont} from '@remotion/google-fonts/Heebo';

const {fontFamily} = loadFont('normal', {
  weights: ['900'],
  subsets: ['hebrew', 'latin'],   // שניהם. ראה למטה.
});
```

### שלוש מלכודות בטעינת הפונט

1. **`subsets: ['hebrew']` חובה** — בלעדיו אותיות עבריות יוצאות ריבועים.
2. **`'latin'` חובה גם כן** — בלעדיו ספרות (`600`) ומילים באנגלית נופלות לסריף
   של המערכת. זה נראה שבור וקל לפספס אם בודקים רק טקסט עברי.
3. **`loadFont` לא קובע `font-weight`.** הוא טוען את הקובץ בלבד. בלי
   `fontWeight: 900` מפורש על האלמנט הדפדפן מרנדר ב-400, והכתוביות יוצאות
   בולד רגיל במקום שחור.

### איך לבחור פונט לפרויקט אחר

**לא לפי הרגל.** להגדיל מילה אחת מהרפרנס, לרנדר מועמדים באותו גודל, ולהשוות
צורות אותיות. בפרויקט המקורי ההנחה הראשונה הייתה Assistant Bold — הסטנדרט
הכתוב של אותו לקוח — והיא הייתה שגויה; הוא נכתב למשימה אחרת.

## צבעים

לדגום מהרפרנס, לא להמציא.

| רכיב | ערך |
|---|---|
| רקע | `#1B1C20` |
| טקסט | `#FFFFFF` |
| הדגשה אדומה | `#FA0000` |
| הדגשה זהב | `#CCC0A6` |

**על זהב — טקסט כהה.** לבן על `#CCC0A6` הוא ניגודיות ~1.7:1 ולא קריא. גם אם
ברפרנס זה נראה לבן, שם היה רקע בהיר שעזר.

## מבנה הבלוק

2–3 שורות במקבץ אחד:

| מצב | תצוגה |
|---|---|
| שורה שכבר נאמרה | גודל רגיל, אטימות מלאה |
| השורה הפעילה | **גדולה יותר**, אטימות מלאה, קפיצה של 15% ב-180ms |
| שורה שעוד לא נאמרה | גודל רגיל, 45% אטימות |

ההפרש בין הפעילה לשכנות הוא כל הסגנון.

### שורות קצרות — מקסימום ~17 תווים

שורה ארוכה מתכווצת כדי להיכנס לקנבס, וזה **הורס את הפרש הגודל**. בפרויקט
המקורי שורה פעילה התכווצה מ-96px ל-80px בזמן שהשכנות ב-78px — ההיררכיה נעלמה.

**האינווריאנט הנכון:** ״הפעילה נשארת גדולה ב-12% לפחות מהשכנות״ —
לא ״לעולם לא מתכווצת״. הכלל השני מחמיר מדי ופוסל שורות תקינות.

**התיקון האמיתי הוא עריכתי:** לפצל שורות ארוכות לפי חותמות המילים. רפרנסים
טובים משתמשים ב-2–4 מילים לשורה.

---

## ⚠️ לא להציג טקסט שלא נשמע

בלוק יכול לחצות סוף של קטע. השורות המעומעמות שלו הן אז **טקסט לדיבור שהקטע לא
מנגן** — הצופה רואה מילים שלא ישמע.

```ts
export const visibleLines = (block: Block, until: number): Line[] =>
  block.lines.filter((l) => l.t < until);
```

**זה לא מספיק לבד.** אם החיתוך נופל 0.05 שניות אחרי תחילת שורה, השורה תיחשב
״נאמרת״ ותוצג — עבור חמישית פריים של דיבור. **החיתוך צריך לנחות לפני שהשורה
מתחילה.**

---

## כל מילה שנאמרת צריכה כתובית

בדיקה שכדאי להריץ ידנית: לעבור על כל מילה בתמלול ולבדוק אם הכתובית שעל המסך
באותו רגע מכילה אותה.

בפרויקט המקורי זה מצא שלושה מקומות שבהם הדובר ממשיך והכתובית תקועה — הגרוע היה
**1.3 שניות** של דיבור בלי כתובית, בדיוק לפני חיתוך.

**להתעלם מ:** הפרשי עיגול של שברירי שנייה, ותיקוני איות מכוונים.

## מבנה הנתונים

```ts
type Line = {
  t: number;        // שנייה במקור — אותו timebase כמו התמלול
  text: string;     // הטקסט הנכון, לא של Whisper
  style: 'plain' | 'red' | 'gold';
};

type Block = {
  lines: Line[];
  end: number;      // שנייה במקור
};
```

**כל התזמונים בזמן־מקור.** לא בזמן־פלט. כך הקונפיג נשאר קריא מול התמלול ואין
שכבת תרגום שאפשר לטעות בה — גם כשיש חיתוכים באמצע.

**בלוקים חייבים להיות רציפים:** `block[i].end === block[i+1].lines[0].t`.
פער של 0.2 שניות משאיר את המסך בלי כתובית באמצע משפט, וזה נראה כמו תקלה.
